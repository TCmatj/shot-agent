# 修复：画布节点视口剔除导致高节点平移时消失

> 作者：matijun　日期：2026-06-14　调试方法：systematic-debugging（superpowers）

### 🎯 目标理解

- **现象**：平移整个画布后，有内容（图片 / 视频 / 长输出 / story）的「高节点」，当其仍有部分在视口内时被剔除而消失；把视口（或节点）往回移一点，节点又重新出现。
- **约束**：
  - 画布为自研实现（未用 tldraw / reactflow / pixi），不得引入重型库。
  - 修复不得破坏：横向剔除、平移冻结（`shouldFreezeVisibleCanvas`）、选中节点豁免、缩放、minimap 等现有行为。
  - 浏览器 + 桌面（Tauri WebView）双运行时均需正常。

### 🧠 分析与思考（根因）

**核心矛盾：剔除用的「节点高度」不等于节点真实可见高度。**

| 环节 | 代码位置 | 高度来源 |
|------|----------|----------|
| 视口剔除（AABB 相交） | `App.tsx:4668-4676` | `getCanvasNodeHeight(node)`，未设 `node.height` 时为默认 **220**（`canvasWorkspace.ts:621,676-682`） |
| 节点渲染 | `App.tsx:10085` | `minHeight: getCanvasNodeHeight(node)` —— **下限**，内容会撑开到远超 220 |

- 有内容的节点真实高度常达 500–1000+，但剔除按 220 判断。
- 当高节点位于视口边缘时：`node.y + 220 < bounds.minY`（按估算判定「已完全出界」），但 `node.y + 真实高度 > bounds.minY`（实际仍有部分在内）→ **误剔除 → 消失**。
- **为何「平移时」最明显**：平移中 `shouldFreezeVisibleCanvas=true`（`App.tsx:4613-4614`），`visibleCanvasNodes` 冻结为上一帧列表（不消失）；平移结束冻结解除、重新执行 `nextVisibleCanvasNodes` → 触发误剔 → 消失。把视口移回一点 → 相交重新通过 → 恢复。与用户观察一致。
- **横向不误剔**：宽度渲染用固定 `width: getCanvasNodeWidth(node)`（`App.tsx:10084`），与剔除一致；唯独高度用 `minHeight`（下限）导致不一致。这解释了问题集中在垂直方向。
- **并发 / 副作用**：纯前端渲染逻辑，无后端、无并发竞争；风险面在「剔除过松 → DOM 节点增多（性能）」或「过紧 → 漏显（当前 bug）」。

### 📋 拟定计划（Artifact: Plan）

**方案对比**（单一修复，不在一次提交中混做）：

| 方案 | 做法 | 改动量 | 评价 |
|------|------|--------|------|
| **A. 最小止血** | 高度方向剔除容差增大（垂直 overscan 或高度下界） | 3–5 行 | 治标：容差需足够大才有效（如 ≥1600），垂直剔除变松、节点多时性能下降；超高节点仍可能漏 |
| **D. 治本（推荐）** | 用 `ResizeObserver` 测量节点真实高度，剔除优先用实测值，fallback 估算 | ~40 行 | 治本：剔除精确，性能好；需处理 observer 生命周期与卸载后保留测量值 |
| C. 估算改进 | 让 `getCanvasNodeHeight` 对有输出节点返回更接近真实的估算 | 中等 | 估算仍不准，图片/视频 intrinsic 尺寸难估，不彻底 |

**推荐：D（治本）**；若需立即止血可先合 A，再做 D。

**D 的实施步骤**：
1. [ ] 提取纯函数 `isNodeWithinViewport(node, bounds, measuredHeight?)`，便于单测（剔除判定与渲染解耦）。
2. [ ] 新增测量 hook（如 `useMeasuredNodeHeights`）：用单个 `ResizeObserver` 观察所有可见节点 `article`，把 `offsetHeight` 写入 `Map<nodeId, number>` ref。
3. [ ] `nextVisibleCanvasNodes` 的相交判断：`height = measured.get(node.id) ?? getCanvasNodeHeight(node)`。
4. [ ] 节点卸载不清除其测量值（避免「首次进入视口前无测量值 → 退回估算 → 边缘闪烁」）。
5. [ ] 验证：浏览器 + 桌面双运行时。

### 🚨 风险评估与回滚

- **风险**：
  - observer 数量：用「单 observer 观察多目标」而非每节点一个，避免句柄膨胀。
  - 桌面兼容：`ResizeObserver` 为现代 Web 标准，Tauri 的 WebView2（Win）/ WKWebView（mac）均支持；仍需在桌面端实测。
  - 内存泄漏：组件卸载 / 画布切换时必须 `disconnect()`。
  - 首帧：首次渲染尚无测量值，fallback 到估算，可能在第一帧短暂误剔、下一帧修正（可接受）。
- **回滚**：改动集中于「剔除 height 来源 + 一个测量 hook」，单提交 `git revert` 即可还原；无数据 / 存储 / schema 变更，无灰度配置需求。

### Code Review（模拟苛刻审查）

- ⚠️ **只观察可见节点会自我矛盾**：observer 只能挂在已渲染（visible）的节点上；而被误剔的节点恰恰是「应可见却被剔除」的。→ 缓解：测量值缓存在 ref 且**卸载不清除**，节点再次进入视口时已有历史测量值可用；首帧 fallback 估算仅影响首次出现。
- ⚠️ **测量滞后**：内容（图片/视频）加载后高度变化，需确保 observer 在内容变更后触发回调（`ResizeObserver` 对内容盒变化会触发，需确认观察的是 border-box / content-box 正确选项）。
- ⚠️ **缩放下的一致性**：缩放改变的是视口变换，节点 canvas 尺寸不变，`offsetHeight`（CSS 像素）需与 canvas 坐标一致——节点用 `translate3d` 在 canvas 坐标系，`minHeight` 单位是 canvas 像素，`offsetHeight` 受 `scale` 影响应换算回 canvas 坐标。→ 实现时统一换算：`canvasHeight = offsetHeight / scale`。
- ✅ 横向无需测量（宽度固定）。
- ✅ 不触碰持久化、生成任务、存储层，影响面可控。
